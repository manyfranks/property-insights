## This is a build-ahead

The proposal (`insurance-distribution-proposal.html`, `#stages`) explicitly gates Stage 2 on
**Stage 0 conversion evidence** — proof that property-analysis traffic actually converts to
insurance intent, generated by the county-page content modules and blog post. That evidence does
not exist yet. This branch builds Stage 2 anyway, ahead of the gate, so the flow is ready to flip
on the moment Stage 0 data justifies it (or ahead of a partner conversation that wants to see the
real thing rather than a deck). **Nothing in this build ships to a real user until both**
`NEXT_PUBLIC_INSURANCE_INTAKE` **is turned on and the Stage 0 decision gate is separately cleared** —
the flag is a kill switch, not a substitute for the gate.

## What Stage 2 is

Per the proposal: confirm the property (pre-filled from data we already hold), ask up to six
underwriting-relevant questions, route by jurisdiction and coverage line, hand off to the matched
partner's quote flow pre-populated. The stored profile is the strategic asset — a warm pipeline
and conversion proof for negotiating equity later rather than accepting a flat per-lead fee (see
`INSURANCE-BROKERAGE-STRUCTURES.md` §5).

## What's being built

Status noted per item — this branch is mid-build, and this doc is written to stay accurate as it
progresses rather than describe a finished state that doesn't exist yet.

- **Registry extensions — built.** `src/config/affiliate-vendors.ts` gains `InsuranceLine`
  (`homeowner | landlord | tenant | strata | commercial`) and a `prefill` declaration
  (`url-params | smart-link | api`, plus notes) on `AffiliateVendor`. Three inert entries added:
  `zensurance` (CA, landlord + commercial, application in review), `steadily` (US, landlord,
  Ambassador tier already held, smart-link prefill), `obie` (US, landlord + strata + commercial,
  BD thread live, API prefill). All three ship `enabled: false, affiliateReady: false` — declared
  in the registry so Stage 2 routing can be built against real data without a fresh capability
  audit, but rendering nothing until each partnership actually closes.
- **`coverage_profiles` persistence — built.** `src/lib/db/schema.sql` adds the `coverage_profiles`
  table (property snapshot as JSONB with per-field `known`/`modeled` provenance, the six-question
  answer set, `vendor_id` nullable until handoff, and a `consent BOOLEAN CHECK (consent = TRUE)`
  constraint enforced at the DB layer, not just in application code). `src/lib/db/coverage-profiles.ts`
  is the write/read path — fail-loud validation, throws rather than silently drops a malformed or
  unconsented profile. `src/app/api/coverage-profile/route.ts` is the API surface; it 404s while
  `NEXT_PUBLIC_INSURANCE_INTAKE` is off. `scripts/migrate-coverage-profiles.ts` is the one-time
  table-creation script — delivered, **not executed** against a real database as part of this
  branch. Flag-off in production regardless of code state until the privacy amendment lands (see
  `DRAFT-PRIVACY-AMENDMENT-COVERAGE-PROFILE.md` §4) — user_id is stored NULL for opted-out
  visitors (GPC / Do-Not-Sell), matching the existing `partner_clicks` pattern, so the profile
  persists without account linkage exactly as that draft describes.
- **Prohibited-terms build guard — built.** `scripts/check-insurance-copy.ts` scans every
  `vertical: "insurance"` vendor's copy fields (`ctaLabel`, `description`, `shortCta`, `offerText`)
  for solicitation-adjacent terms — "compare," "comparison," "best," "top-rated," "recommended,"
  "cheapest," "lowest" — and fails the build on a hit. Wired into `package.json`'s `prebuild`
  script ahead of `generate-sitemap.ts`, so it runs on every build, not just CI. Scope is
  deliberately insurance-only (mortgage CTAs like "Compare mortgage rates" are unaffected). This is
  the code-level enforcement of the copy discipline `INSURANCE-BROKERAGE-STRUCTURES.md` §3 and the
  proposal both call structural, not a style preference.
- **`partner-connect` route extension — built.** Now accepts an opaque, shape-validated
  `profileId` (UUID) so an insurance click-through can be linked to its coverage profile for
  click-through analytics, without the route itself ever reading or transmitting the profile's
  contents.
- **Result-page insurance module — built.** `src/components/insurance/insurance-module.tsx`:
  line chooser (homeowner / landlord / tenant / strata / commercial, commercial marked Beta) plus
  a partner slate rendered from the affiliate registry (hero + up to two pills, quiet
  licensed-broker fallback when no vendor covers the line), jurisdiction-gated via
  `INSURANCE_STATE_EXCLUSIONS` / `INSURANCE_LINE_EXCLUSIONS`. Mounted on the CA property view and
  the US full-assessment view of `src/app/property/[slug]/page.tsx`, and on `UsListedView` /
  `UsOffMarketView` in `src/components/us-assessment-result.tsx`. Degraded views (US sparse
  listing, fallback, limited-rental) deliberately skip it — no reliable data to seed a profile.
- **Intake — Variation A, stepped wizard — built.** `src/app/coverage-profile/page.tsx` (server:
  flag gate, jurisdiction gate with a visible exclusion notice, listing-backed prefill) +
  `src/components/insurance/coverage-profile-wizard.tsx` (4 steps: confirm prefill with
  Known/Modeled provenance chips and honest "not on file" rows → line → occupancy+underwriting
  answers → contact+consent; submit POSTs `/api/coverage-profile`, errors surface inline).
- **Handoff page — built.** `src/components/insurance/coverage-handoff.tsx`: a provenance summary ("here's what we're sending, and
  to whom") followed by an "Outcome" framing screen, not a "your quote" framing. This is
  deliberate copy discipline: the proposal's compliance rule (`insurance-distribution-proposal.html`,
  "Build your property's coverage profile → get matched with a licensed broker," never "compare
  quotes") extends to the handoff step — describe an outcome (matched with a partner), never imply
  we produced a quote or comparison ourselves. The `vendor_id` column on `coverage_profiles` is
  already shaped to record the handoff target once this page writes to it.

## What is deliberately NOT built

- **Screen 5 — instant quote.** The proposal's terminal step for Stage 2 is a *handoff* to the
  partner's own quote engine, not an in-app quote. An in-app instant-quote screen is Stage 3
  territory (`insurance-distribution-proposal.html` §stages, Stage 3: "licensed structure") and
  must not ship while we're unlicensed — presenting quote terms ourselves is the solicitation line
  `INSURANCE-BROKERAGE-STRUCTURES.md` §3 and `PARTNER-LANDSCAPE-2026-08.md` §2/§4 both warn about.
  Not scaffolded, not stubbed behind a flag — simply not part of this build.
- **Lemonade.** Excluded per `PARTNER-LANDSCAPE-2026-08.md` §3: bind-contingent payout conflicts
  with the flat non-contingent compensation envelope this program is built around, and its
  landlord coverage is condo/co-op-only in roughly 8 jurisdictions. No registry entry exists or is
  planned.
- **Live edits to `src/app/privacy/page.tsx` or `src/app/data-usage/page.tsx`.** Both pages are
  counsel-prepped. `DRAFT-PRIVACY-AMENDMENT-COVERAGE-PROFILE.md` is the proposed redline; the live
  pages are untouched by this branch and stay that way until counsel signs off and a separate,
  explicit change lands them.

## Feature flag

`NEXT_PUBLIC_INSURANCE_INTAKE` gates every user-facing surface built on this branch — the result-page
module, the intake wizard, and the handoff page. Off by default. Turning it on is a distinct
decision from merging this branch, and depends on both:

1. The Stage 0 conversion-evidence gate (see "This is a build-ahead," above) — build-ahead status
   is explicitly disclosed here so nobody mistakes a merged branch for a cleared gate.
2. The privacy amendment landing on the live pages, per `DRAFT-PRIVACY-AMENDMENT-COVERAGE-PROFILE.md`.

## Decision gates carried over from the proposal

Restated here so this build record doesn't drift from the source proposal:

- Stage 2 (this branch) is gated on Stage 0 evidence that property-analysis traffic converts to
  insurance intent — not yet cleared, hence "build-ahead" above.
- Stage 3 (licensed structure) is gated on Stage 2 volume and requires counsel — out of scope for
  this branch entirely; nothing here should be read as progress toward Stage 3 beyond making the
  Stage 2 pipeline real enough to eventually produce that volume evidence.
- The copy discipline ("coverage profile → matched with a licensed broker," never "compare
  quotes" or "your quote") is structural, not a style preference — see the prohibited-terms guard
  above and `INSURANCE-BROKERAGE-STRUCTURES.md` §3's finding that solicitation is defined by
  behavior, not payment.
