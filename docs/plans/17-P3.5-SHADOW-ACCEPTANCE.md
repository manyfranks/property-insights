# P3.5 Shadow Acceptance and Rollout Boundary

_Created 2026-08-11. Acceptance layer between P3 classification/capabilities and P4 goal UX._

## Outcome

P3.5 makes the shadow classifier observable without changing any visible result, user journey, CTA, or provider-call path. It also measures the evidence actually present in the persisted Discover corpus instead of treating enriched fixtures as representative of seeded listings.

The rollout boundary is:

- **On-demand assessment may proceed to a flagged P4 pilot** after production telemetry is verified. Its bundle can carry P1 evidence, P2 subject resolution, P3 classification, and capability decisions.
- **Discover is excluded from P4 persona routing for now.** Nearly the entire persisted corpus predates P1 and lacks the evidence envelope needed for honest classification.
- **No paid/provider backfill is authorized.** Discover earns capability through normal guarded refreshes and future evidence-preserving ingestion. Coverage must be measured before routing is enabled there.
- **Occupancy remains shadow-only.** This work does not store its value in telemetry or use it for visible personalization.

## Anonymous operational stream

P3.5 uses `property_intelligence_events`, a separate 90-day operational stream rather than `user_events` or `user_profiles`.

It stores only:

- event type;
- country and coarse state/province code;
- ingestion surface and result variant;
- subject scope, resolution confidence, and clarification requirement;
- classification value/state/confidence summaries and non-identifying tag names;
- capability reason codes.

It does **not** store a user ID, address, unit identifier, place ID, owner/occupancy value, assessment goal, journey, intent, raw evidence, provider record, source payload, or explanation. The write runs as a post-response task and cannot block or fail the assessment response.

Implementation fixtures assert the privacy boundary and make zero network/provider calls.

## Release gates

- [x] Anonymous telemetry has a dedicated schema and 90-day retention.
- [x] Telemetry fixtures reject identity, address, unit, occupancy, goal, intent, raw evidence, and explanation fields.
- [x] Discover replay makes zero provider calls and preserves quota (`50 -> 50`).
- [x] Unknown and conflicting evidence degrade neutrally.
- [x] Discover and on-demand evidence tiers are reported separately.
- [ ] Production assessment emits queryable anonymous events after deployment.
- [ ] Matt reviews mixed-use, apartment-unit, land, and institutional fixture outcomes.
- [ ] Counsel/privacy review completes before occupancy affects visible personalization or routing.
